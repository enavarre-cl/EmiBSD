# xtask (host tooling)

- Host-only Rust with `std`. Never depends on `bsd` or `libkern`; never compiled for a bare target.
- Invoked as `cargo xtask <cmd>` (alias in `.cargo/config.toml`). The workspace root is derived
  from `CARGO_MANIFEST_DIR`, never from the current directory.
- Subcommands: `image` (FAT ESP with Limine + `/bsd`), `qemu` (run), `smoke` (run, assert serial
  lines and exit code), `smoke2` (two VMs on a private link, `twovm.rs`), `smoke-all`
  (`just smoke`'s recipes N at a time, each in `target/smoke/<recipe>`, under an outer
  watchdog that kills a recipe's process tree past its summed boot limits or after ten
  minutes of a still log, `smokeall.rs`), `lz {check,status,drift,trace}` (`lz.rs`: the lineage against EmiBSD.LZ, `lineage.md`, `lz-sync.md`; `check` also validates the zone markers of every `.rs` under `sys/` and `tools/`: `layout.rs`, M15; `drift --functions` maps the LZ items a pending commit touches to the native items that own them now; `trace` answers LZ -> native, native -> LZ and C -> native; the LZ item lexer is line-based, in the house style of `unsafe-report`), `unsafe-report [--write|--check] [--shapes]` (`unsafe` per subsystem, `unsafereport.rs`; the zero-unsafe groups of `unsafe-core.toml`: core, `forbid` modules read from the module tree, legacy; the shape counts, per module with `--shapes`; `--check` against `unsafe-budget.toml`'s rows and `[ratchet]` (`forbid_floor`, `legacy_ceiling`), `unsafe-budget.md`; `--write` lowers budgets and the ceiling and raises the floor, never the other way; `lz check` also refuses a hand-written `Adapter` impl and a `redesigned` module outside the core that is not `forbid`), `diff-openbsd` (M12+: EmiBSD against a real OpenBSD VM, `diffopenbsd.rs`; its `powerbtn` (M16f) and `probe` (M16e) boot that OpenBSD alone: `probe --arch A [--ipmi] [--nic MODEL] [--usb] [--usb-hc xhci|ehci|uhci|ohci] [--ukc CMD]... [--sh CMD]` with the smokes' device options (`--ipmi`, `--nic` (M16c: the model in virtio-net's place, left unconfigured, so `--sh` sets it up), and `devices.rs`'s `--usb`/`--usb-hc`, M16b; M16d: `--virtio-rng`, `--balloon`, `--virtio-gpu`, `--parallel`, `--pcspk`, `--audio es1370`, and the `--sendkey-after`/`--monitor-after` pairs fired while `--sh` runs), `boot -c` and the UKC commands given, and records its dmesg and CMD's output in `<run dir>/<arch>/openbsd-probe.log`, which is how a driver is checked against what OpenBSD 8.0 does on the same machine), `gen-syscalls`, `symbolize`, `ntfs-image` (M10d: our NTFS test volume, `ntfsgen.rs`, checked by macOS's NTFS driver), `efiboot` and `efiboot-disk` (M14: BOOTX64.EFI from the efiboot ELF with the toolchain's llvm-objcopy, and `smoke-efiboot`'s MBR + disklabel + makefs FFS + ESP disk, `efiboot.rs`), `install-img`, `cd-iso`, `install80` and `cd80` (M16g, `distrib.rs`: `install80.img` and amd64's `cd80.iso` as `distrib/` lays them out, the ISO 9660 image written by `iso9660.rs` as mkhybrid writes it; the install from the image as a USB stick, answered over the console, `--image FILE` for OpenBSD's own image; the CD booted to the installer; `boot.rs`'s `BootMedium` puts the boot image on a USB stick or a CD), `nvme-root` (M13a: the labelled root disk of `smoke-nvme` and `smoke-ahci`, `--root-dev sdNa` naming its fstab root when it is not `sd0a`; `hwopts.rs`, which also holds M13's QEMU device options: `--nvme`, `--ahci`, `--scsi-cd`, `--lsi FILE` with `--lsi-cd ISO`, `--reboot` for a guest reset that restarts the VM, `--vio-mq` for a multiqueue virtio-net vio0 (`mq=on`, MSI-X, intrmap), `--pci-bridges` for virtio-blk disks behind a `pcie-root-port` and a `pci-bridge` (M16e, ppb(4), `smoke-ppb`), and M14's `--acpi` (arm64 `virt,acpi=on` with PCI virtio disks and NIC, booted through efiboot's ACPI tables: `smoke-acpi`), `--nic MODEL` replacing vio0 on the user network with QEMU's `e1000`, `e1000e` or `igb` (M13, em(4)), `rtl8139` (re(4)), `vmxnet3` (vmx(4)), or M16c's `pcnet` (pcn(4)), `i82559er` (fxp(4)), `ne2k_pci` (ne(4)) and `tulip` (dc(4)), `--iommu intel|amd` (M16e, amd64: QEMU's `intel-iommu` or `amd-iommu,dma-remap=on` on q35, the virtio PCI devices then `disable-legacy=on,iommu_platform=on`; `smoke-dmar`), `--machine pc` for i440fx's `pc` instead of `q35` on amd64 (M16e, piixpm(4), `smoke-iic`; refused on arm64 and with `--ahci` or `--pci-bridges`), `--ipmi` for QEMU's simulated BMC (`ipmi-bmc-sim` with an SDR file written in the run directory) behind `isa-ipmi-kcs` on amd64 (M16e, ipmi(4), `smoke-ipmi`), `--virtio-rng`, `--balloon` and `--virtio-gpu` (M16d, both archs: QEMU's virtio entropy device, memory balloon and GPU for viornd(4), viomb(4) and viogpu(4), `virtio-*-pci` on amd64 and arm64 `--acpi`, `virtio-*-device` on arm64), `--parallel FILE` with `--expect-parallel TEXT` (M16d, amd64: the first parallel port, lpt(4), into FILE in the run directory), `--tpm tis|crb` (M16e, amd64: QEMU's `tpm-tis` or `tpm-crb` backed by a `swtpm` that each run starts in its run directory and always stops, `smoke-tpm`), `--fb` for a GOP display (`ramfb` on arm64), `--screenshot-after LINE` for a QEMU `screendump` (implying `--fb`, but with `--virtio-gpu` the GPU is the display, M16d) checked against the kernel's `selftest=fb` line (or, with `--screen-text ROW:COL:TEXT`, for TEXT on wsdisplay's grid that `selftest=wscons` describes), `--sendkey-after LINE --sendkeys KEYS` (repeatable) for QEMU monitor `sendkey`s on the guest keyboard once LINE is on the serial line (`smoke-kbd`), `--usb-mouse`, `--usb-tablet`, `--usb-wacom-tablet`, `--usb-ccid`, `--usb-net` and `--usb-serial FILE` (M16b: QEMU's USB pointers, smart card reader, `usb-net` (the user network's NIC in vio0's place, for cdce(4)) and `usb-serial` (an FTDI FT232 whose chardev is FILE in the run directory, with `--usb-serial-send-after LINE --usb-serial-send TEXT` for what the guest reads and `--expect-usb-serial TEXT` for what it must write, for uftdi(4) and ucom(4)) on the `--usb-hc` controller's bus (full speed: xhci, uhci or ohci), with or without `--usb`; `devices.rs`; pointer events then come from `--monitor-after LINE --monitor 'mouse_set N'`/`'mouse_move DX DY'`/`'mouse_button STATE'`), and `{host-ms}` in a `--send` text, the host clock as it is sent), `--audio usb` (M16b: QEMU's `usb-audio` on the `--usb-hc` controller's bus (full speed: xhci, uhci or ohci) into the `wav` backend, beside M12's `--audio hda|ac97`, so `--expect-tone` checks uaudio(4); `devices.rs`), `--audio es1370` and `--pcspk` (M16d, amd64: QEMU's ES1370 for eap(4), and the PC speaker through `-machine pcspk-audiodev` for pcppi(4), into the same `wav` backend), the USB and audio devices of `devices.rs` (M12: `--usb` for a `qemu-xhci` with the FAT32 `usb-storage` stick and a `usb-kbd`, `--audio hda|ac97`, `--speakers`, `--expect-tone`; M16b: `--usb-hc xhci|ehci|uhci|ohci`, implying `--usb`, the host controller the stick sits on, `usb-ehci` for ehci(4) with the stick alone since QEMU refuses a full speed `usb-kbd` on a companionless EHCI, `piix3-usb-uhci` for uhci(4) and `pci-ohci` for ohci(4), each with the stick and the keyboard (full speed ports, so the M16b pointers and `usb-audio` fit too); a new controller is one arm of `UsbHc`), M16a's storage controllers (`storage.rs`, one option per controller with its disk FILE in the run directory, made afresh each run, added after every other device: `--ide` (amd64 `--machine pc`, PIIX3's primary master), `--megasas`, `--megasas-gen2`, `--mptsas`, `--pvscsi`, `--am53c974`, `--dc390`, `--ufs`, `--sdhci` (64 MiB of zeroes) and `--floppy` (amd64, a FAT12 1.44 MB image xtask writes, in drive B); `diff-openbsd probe` takes them and `--machine pc` too), `userland`
  (M8: OpenBSD's libc and programs cross-compiled from the reference sources, `userland.rs` over
  the make-subset evaluator `bsdmake.rs`; M16c: the base set's `/etc/firmware/fxp-*`
  files, which `sys/dev/microcode/fxp/build.c` writes, made from `rcvbundl.h` by
  `userland/firmware.rs`; a worktree's first build, and its first `comp`, is seeded from the
  main checkout's by an APFS clone with the paths rebased, `userland/seed.rs`), `comp` (M14: OpenBSD's clang, lld and libc++ from
  `gnu/llvm` by its build glue, `userland/comp.rs`; outside `ci`, `just comp`).
- External tools (`qemu-system-*`, Limine binaries, EDK2 firmware) are located at runtime via
  `brew --prefix <formula>` or `$PATH`, with an error that names the missing formula and points to
  `docs/SETUP.md`. Never hardcode `/opt/homebrew` or `/usr/local`. Exception: `userland`'s
  toolchain, approved by the user on 2026-10-03, defaults to `/usr/bin/clang` and
  `~/.swiftly/bin` (LLD 17, llvm-ar, llvm-ranlib, llvm-objcopy, llvm-objdump), overridable with
  `$EMIBSD_CC` and `$EMIBSD_LLVM_BIN`.
- Network: nothing downloads but `diff-openbsd fetch` (approved by the user on 2026-10-05) and
  `lz drift --fetch` (`git -C reference/emibsd-lz fetch` from the remote `lz/PINNED.md` names):
  only the snapshot that `openbsd-snapshot.toml` records, only from the mirror it names, with
  macOS's `curl` and `shasum`, into `target/openbsd/`, refused unless both recorded hashes
  match. A new snapshot is the user's decision. Its binaries are test fixtures: never
  committed or redistributed. The OpenBSD VM's first boot has no network (`restrict=on`).
- Workspace lints apply here too: no `unwrap`/`expect`; return `Result` and print one clear
  `xtask: <what failed>: <why>` line. Non-zero exit on any error.
- Keep dependencies minimal: `serde` + `toml` for the lineage and sync files, `fatfs` for images.
  No `clap`; argument parsing is a `match` on `std::env::args`.
- Two commands write to the tree: `lz status --write`, only between the `<!-- lz:begin -->` /
  `<!-- lz:end -->` markers in `README.md` (the table) and `docs/STATUS.md` (the summary line), and `unsafe-report --write`,
  only the line of `docs/STATUS.md` that starts with `Unsafe` and `unsafe-budget.toml`
  (the budgets lowered and the `[ratchet]` moved the good way only: the floor up, the ceiling
  down).
